Create new practice problems for Review Drill. Arguments: `$ARGUMENTS`
(language, difficulty, optional count (default 3), optional format, optional `weak` to target weak spots).

If `weak` is given, run `uv run python -m app.cli stats` first and bias issue categories and
languages toward the highest miss rates.

## What a good problem looks like

- It reads like code an AI assistant would plausibly produce: idiomatic, compiles, confident. Bugs are
  subtle and realistic (spec mismatch, wrong assumption about surrounding code, swallowed errors,
  missing edge case, unsafe input handling, N+1, locking), never cartoonish.
- It has a short **spec** (ticket id + 1–3 sentences of intent) and **context** (what the code runs in).
  Spec mismatches are first-class issues (category `spec`): code that works but does not do what the ticket asks.
- No hints: no comments pointing at bugs, no names like `buggy` or `unsafe`.
- Mix of verdicts across a batch: roughly 20% clean (`approve`, no issues), 10% `nits` (only low-severity
  issues), some `ask` (spec or context leaves out something needed to judge; explain what in the key's
  single `spec` issue or leave issues empty), the rest `changes`.
- Sizes: function 10–40 lines; diff 10–60 lines; multi-file 2–4 files, 40–150 lines total.
  Hard problems hide the issue across files or behind a correct-looking abstraction.

## Files to write

For each problem, pick a new id `<lang>-<short-slug>` (check `data/problems/` for clashes), then write:

1. `data/keys/<id>.json` first:
   `{"problem_id", "verdict": "approve|nits|changes|ask", "issues": [{"id": "k1", "file", "start", "end",
   "category": "correctness|security|performance|design|spec", "severity": "low|medium|high|critical",
   "title", "explanation", "fix"}]}`.
   Line numbers are 1-based rows as displayed. Keep ranges tight: the lines where the fix goes.
2. `data/problems/<id>.json`:
   `{"id", "title", "language", "format": "function|diff|multi", "difficulty", "spec": {"id", "text"},
   "context", "files": [{"path", "content", "is_diff"}], "source": {"kind": "generated", "date": "<today>",
   "notes": "Generated by /generate"}}`.
   For diffs set `"is_diff": true` and start every line with `" "`, `"+"` or `"-"`.
   Writing the key first means the problem only appears in the UI once both exist.

Run `uv run python -m app.cli validate data/problems/<id>.json data/keys/<id>.json` and fix until it passes.

## Reporting

Do not reveal the bugs in the terminal. That would spoil the practice. Reply only with the list of new
problem ids, language, format and difficulty.
